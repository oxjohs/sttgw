# 3차 작업계획서

## 1. 목적

본 문서는 `sttgw` 프로젝트의 3차 작업 범위와 구현 원칙을 정의한다.  
3차의 핵심 목표는 지금까지 작성된 핵심 로직에 대해 문서 기준의 단위 테스트를 추가하고, `compileJava` 및 `test` 실행을 통해 실제로 동작을 검증하는 것이다.

이번 차수는 기능 확장보다 검증을 우선한다.

## 2. 단일 진실 기준

3차 작업은 아래 문서를 기준으로 한다.

- `AGENTS.md`
- `docs/ARCHITECTURE.md`
- `docs/CONVENTIONS.md`
- `docs/SCHEMA.md`
- `docs/DEPLOYMENT.md`
- `docs/1차-작업계획서.md`
- `docs/2차-작업계획서.md`

문서와 코드가 충돌하면 문서를 우선한다.

## 3. 현재 상태

- 현재 테스트는 `SttgwApplicationTests` 1개뿐이다.
- `SipParser`, `RtpPacket`, `G711Codec`, `WavFileWriter`, `SttAdapterFactory`, `CallSessionManager` 에 대한 명시적 단위 테스트가 없다.
- 최근 단계에서 의존성 정리 후 `./gradlew compileJava`, `./gradlew test` 는 성공했다.
- 그러나 이는 실제 핵심 로직의 동작 보장을 의미하지 않는다.

## 4. 3차 작업 목표

이번 3차 작업의 세부 목표는 아래와 같다.

1. 문서상 필수 테스트 대상에 대한 단위 테스트를 추가한다.
2. 통화 세션 생성/종료, SIP 파싱, RTP 헤더 파싱, 코덱 변환, WAV 생성, STT 어댑터 선택 로직을 검증한다.
3. 테스트 작성 과정에서 드러나는 작은 결함은 최소 범위에서 보정한다.
4. 최종적으로 `compileJava` 와 `test` 를 실행하여 실제 성공 여부를 확인한다.

## 5. 테스트 범위

### 5.1 sip

대상:

- `SipParser`

검증 항목:

- `INVITE` 메시지에서 `Call-ID`, `From`, `To`, `mediaPort`, `mediaIp`, `codec` 추출
- `BYE`, `CANCEL` 메서드 구분
- 잘못된 형식 입력 시 null 처리

### 5.2 rtp

대상:

- `RtpPacket`
- `G711Codec`

검증 항목:

- RTP 헤더 파싱
- `version`, `payloadType`, `sequenceNumber`, `timestamp`, `ssrc`, `payload` 추출
- 짧은 입력에 대한 예외 처리
- A-law / u-law PCM 변환 결과의 기본 정확도

### 5.3 audio

대상:

- `WavFileWriter`

검증 항목:

- WAV 헤더 `RIFF`, `WAVE`, `fmt `, `data` 시그니처 존재
- 데이터 길이에 따른 파일 크기 일치

### 5.4 stt

대상:

- `SttAdapterFactory`

검증 항목:

- 기본 벤더 선택
- 사용 가능한 벤더만 반환
- 미지원 벤더 요청 시 예외 발생

### 5.5 session

대상:

- `CallSessionManager`

검증 항목:

- `INVITE` 로 세션 생성
- `BYE` 로 세션 종료 및 저장
- `CANCEL` 로 세션 취소
- `appendAudio()` 시 PCM 누적 및 리스너 호출

## 6. 제외 범위

이번 3차에서는 아래 범위를 제외한다.

- 실제 `capture` 패킷 입력 테스트
- 실제 `Google STT` 호출 테스트
- `WebSocket` 브로드캐스트 테스트
- 전체 애플리케이션 통합 시나리오 테스트
- 실제 파일 저장 후 DB 재조회까지 포함한 통합 검증

이 영역은 후속 차수의 통합 테스트에서 다룬다.

## 8. 예상 리스크

### 8.1 테스트가 실제 설계 문제를 드러낼 가능성

- 테스트 작성 중 현재 구현의 작은 결함이나 테스트 곤란 구조가 드러날 수 있다.
- 이 경우 리팩터링은 최소 범위에서만 허용한다.

### 8.2 비동기 처리 검증 한계

- `AudioFileService` 의 비동기 저장은 단위 테스트보다 통합 테스트에 더 적합하다.
- 이번 단계에서는 `WavFileWriter` 중심으로 직접 검증하고, `AudioFileService` 는 후속 단계로 넘긴다.

### 8.3 코덱 정확도

- `G711Codec` 은 테스트 벡터 부재 시 완전한 참값 검증이 어렵다.
- 이번 단계에서는 대표 입력의 결과와 배열 길이, 부호/값 경향을 우선 검증한다.
