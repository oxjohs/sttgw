# 6차 작업계획서

## 1. 목적

본 문서는 `sttgw` 프로젝트의 6차 작업 범위와 구현 원칙을 정의한다.  
6차의 핵심 목표는 미러링된 UDP 패킷을 실제 애플리케이션 내부 플로우로 연결할 `capture` 패키지를 추가하는 것이다.

이번 차수에서는 운영 환경 의존성이 큰 구간을 도입하되, 로컬 개발과 테스트 안정성을 해치지 않도록 기본값을 보수적으로 설계한다.

## 3. 현재 상태

- `capture` 패키지는 아직 존재하지 않는다.
- `sip`, `rtp`, `session` 계층은 이미 구현되어 있어 패킷 입력만 연결되면 내부 흐름을 탈 수 있다.
- Pcap4J 의존성은 `build.gradle` 에 이미 반영되어 있다.
- 현재 `application.yaml` 은 최소 설정만 가지고 있어 캡처 기본 동작 정책이 드러나지 않는다.

## 4. 6차 작업 목표

이번 6차 작업의 세부 목표는 아래와 같다.

1. `capture` 패키지의 핵심 클래스 3개를 추가한다.
2. `eth3` 기반 패킷 캡처 루프를 구현한다.
3. UDP 패킷을 SIP 와 RTP 로 구분해 기존 모듈로 전달한다.
4. pcap 파일 저장을 비동기 처리로 분리한다.
5. 로컬 개발과 테스트 환경에서는 캡처가 자동 시작되지 않도록 기본 비활성화한다.
6. 구현 후 `compileJava` 와 `test` 로 실제 검증한다.

## 5. 작업 범위

### 5.1 capture

생성 대상:

- `capture/CaptureProperties`
- `capture/PacketDumpWriter`
- `capture/PacketCaptureService`

역할:

- 캡처 설정 바인딩
- 일자별 pcap 파일 저장
- 패킷 캡처 스레드 시작/종료와 SIP/RTP 분기 처리

### 5.2 configuration

수정 대상:

- `src/main/resources/application.yaml`

역할:

- 로컬 안전 실행을 위한 `capture.enabled` 기본값 명시

## 6. 설계 원칙

### 6.1 기본 비활성화

- 운영 문서상 캡처 인터페이스는 `eth3` 이지만, 개발 환경에서는 해당 인터페이스와 권한이 없을 수 있다.
- 따라서 `capture.enabled` 기본값은 `false` 로 둔다.
- 활성화 전까지는 컨텍스트 로딩과 테스트를 방해하지 않아야 한다.

### 6.2 비동기 디스크 I/O 분리

- 캡처 스레드에서 직접 pcap 파일을 쓰지 않는다.
- `PacketDumpWriter` 의 단일 스레드 executor 로 넘겨 캡처 지연을 줄인다.

### 6.3 기존 모듈 경계 유지

- `capture` 는 `sip`, `rtp`, `session` 에 신호만 전달한다.
- SIP 파싱 로직과 RTP 디코딩 로직은 기존 패키지에 그대로 둔다.

### 6.4 보수적 실패 처리

- 패킷 캡처 초기화 실패 시 애플리케이션 전체를 강제 종료하지 않는다.
- 오류를 로그로 남기고 캡처 루프만 종료한다.

## 7. 제외 범위

이번 6차에서는 아래 범위를 제외한다.

- 실제 `eth3` 접근 통합 테스트
- root 권한 또는 `CAP_NET_RAW` 설정 자동화
- 패킷 재생 기반 오프라인 캡처 리더
- 캡처 모듈 전용 대시보드 상태 화면
- RTP 지터 버퍼나 재정렬 로직

## 9. 예상 리스크

### 9.1 운영 권한 의존성

- 실제 캡처는 `libpcap` 설치와 네트워크 권한이 필요하다.
- 이번 차수에서는 이를 코드에서 우회하지 않고, 설정과 로그로만 드러낸다.

### 9.2 RTP 포트 매핑 단순화

- 현재 세션 매핑은 SIP SDP 의 `mediaPort` 기준이다.
- 실제 현장 패킷에서 포트 방향성이 다르면 후속 보정이 필요할 수 있다.

### 9.3 pcap 저장 자원 관리

- 일자별 덤퍼 캐시를 관리하므로 종료 시 자원 해제가 중요하다.
- 이번 차수에서는 종료 훅에서 명시적으로 close 한다.
