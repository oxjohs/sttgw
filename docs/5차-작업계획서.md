# 5차 작업계획서

## 1. 목적

본 문서는 `sttgw` 프로젝트의 5차 작업 범위와 구현 원칙을 정의한다.  
5차의 핵심 목표는 현재까지 구현된 REST API 및 세션 관리 계층 위에 운영자가 사용할 수 있는 대시보드 화면과 WebSocket 실시간 전송 기반을 추가하는 것이다.

이번 차수에서는 화면의 첫 인상과 실시간 반응성을 함께 확보한다.

## 2. 단일 진실 기준

문서와 코드가 충돌하면 문서를 우선한다.

## 3. 현재 상태

- 현재 `dashboard`, `websocket` 패키지는 없다.
- Thymeleaf 템플릿과 정적 자산도 아직 없다.
- REST API 는 구현되어 있어 대시보드와 설정 화면이 사용할 조회/수정 진입점은 존재한다.
- WebSocket starter 의존성은 이미 정리되어 있다.

## 4. 5차 작업 목표

이번 5차 작업의 세부 목표는 아래와 같다.

1. `dashboard` 패키지와 `websocket` 패키지를 추가한다.
2. `/` 과 `/settings` 에 대응하는 Thymeleaf 화면을 구현한다.
3. `/ws/stt` WebSocket 엔드포인트를 구현한다.
4. 세션 생성/종료 이벤트와 STT 결과를 브라우저에 브로드캐스트할 기반을 만든다.
5. 운영자가 한 눈에 상태를 파악할 수 있는 대시보드 UI 를 제공한다.
6. 구현 후 `compileJava` 와 `test` 로 실제 검증한다.

## 5. 디자인 및 상호작용 기준

### 5.1 visual thesis

- 관제실 같은 긴장감과 안정감을 동시에 주는 텔레메트리 대시보드

### 5.2 content plan

1. 상단 상태 요약
2. 활성 통화 목록
3. 실시간 STT transcript 흐름
4. 설정 이동 또는 저장

### 5.3 interaction thesis

- WebSocket 연결 상태 점등
- transcript 도착 시 누적 애니메이션
- 세션 생성/종료 시 활성 목록 즉시 반영

## 6. 작업 범위

### 6.1 dashboard

생성 대상:

- `dashboard/DashboardController`

역할:

- `/` 대시보드 화면
- `/settings` 설정 화면

### 6.2 websocket

생성 대상:

- `config/WebSocketConfig`
- `websocket/SttWebSocketHandler`
- `websocket/WebSocketSessionRegistry`

역할:

- WebSocket 엔드포인트 등록
- 연결 세션 관리
- 세션 이벤트 및 STT 결과 브로드캐스트

### 6.3 templates

생성 대상:

- `templates/dashboard.html`
- `templates/settings.html`

원칙:

- 대시보드는 활성 통화와 transcript 중심 레이아웃으로 구성한다.
- 설정 화면은 현재 STT 설정과 저장 동작에 집중한다.

### 6.4 static assets

생성 대상:

- `static/css/dashboard.css`
- `static/js/websocket-client.js`
- `static/js/dashboard.js`
- `static/js/settings.js`

원칙:

- WebSocket 메시지는 UI 갱신에 바로 연결한다.
- 설정 화면은 REST API 를 통해 PUT 저장한다.

## 7. 보안 및 데이터 표시 원칙

- WebSocket 메시지에는 고객 전화번호 전체를 포함하지 않는다.
- 필요 시 마스킹한 전화번호만 전송한다.
- transcript 표시 시 HTML 삽입이 아니라 텍스트 삽입 방식으로 처리한다.

## 8. 제외 범위

## 10. 예상 리스크

### 10.1 STT 결과 실시간 표시 한계

- 현재 STT 서비스 구현체가 없으므로 실시간 transcript 는 WebSocket 기반과 UI 까지만 준비되고, 실제 결과 유입은 후속 차수에서 연결된다.

### 10.2 화면 테스트 부재

- 이번 차수에서는 브라우저 기반 UI 테스트를 수행하지 않는다.
- 따라서 레이아웃/상호작용은 코드 구조와 정적 검증 중심으로 관리한다.

### 10.3 WebSocket 민감 정보 노출

- WebSocket 메시지에 전체 전화번호를 실수로 담을 위험이 있다.
- 이번 차수에서는 마스킹을 강제한다.
