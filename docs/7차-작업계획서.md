# 7차 작업계획서

## 1. 목적

본 문서는 `sttgw` 프로젝트의 7차 작업 범위와 구현 원칙을 정의한다.  
7차의 핵심 목표는 `SttAdapter` 인터페이스를 구현하는 Google Cloud Speech-to-Text 어댑터를 추가하여, 배치 인식과 스트리밍 인식의 실제 벤더 구현 기반을 마련하는 것이다.

이번 차수에서는 앞서 정리한 `dev` 와 `prod` 환경 프로파일을 기준으로 Google 자격증명 경로를 분리하고, 자격증명 유무에 따라 사용 가능 여부를 판별할 수 있게 만든다.

## 3. 현재 상태

- `stt` 패키지에는 `SttAdapter`, `SttAdapterFactory`, `SttProperties`, `SttResult`, `SttStreamingSession` 만 존재한다.
- `stt/google` 패키지는 아직 없다.
- `api/SttController` 는 어댑터가 존재한다는 전제로 동작하지만, 현재는 실제 Google 구현체가 없어 호출 시 동작 범위가 제한적이다.
- `application-dev.yaml`, `application-prod.yaml` 은 이미 분리되어 있으나, Google STT 구현 클래스는 아직 연결되지 않았다.

## 4. 7차 작업 목표

이번 7차 작업의 세부 목표는 아래와 같다.

1. `stt/google` 패키지를 추가한다.
2. `GoogleSttProperties` 를 추가해 Google 전용 설정을 바인딩한다.
3. `GoogleSttAdapter` 를 구현해 배치 STT 인식을 지원한다.
4. `GoogleSttStreamingSession` 을 구현해 스트리밍 STT 세션 골격을 제공한다.
5. `SttStreamingSession` 인터페이스를 문서 기준에 맞게 보강한다.
6. 자격증명 경로 존재 여부에 따라 `isAvailable()` 를 정확히 판별한다.
7. 네트워크 없는 로컬 테스트를 추가하고 `compileJava`, `test` 로 검증한다.

## 5. 작업 범위

### 5.1 stt/google

생성 대상:

- `stt/google/GoogleSttProperties`

역할:

### 5.2 stt 공통 계약 보강

수정 대상:

- `stt/SttStreamingSession`

### 5.3 테스트

생성 대상:

- `src/test/java/com/oxjohs/sttgw/stt/google/GoogleSttAdapterTest.java`
- 필요 시 스트리밍 세션 테스트

원칙:

- Google 실서버 호출 없이 단위 테스트가 가능해야 한다.
- 자격증명 존재 여부, vendor 이름, 예외 처리, 세션 상태를 우선 검증한다.

## 6. 설계 원칙

### 6.1 어댑터 패턴 유지

- Google 구현체는 `SttAdapter` 를 구현한다.
- 서비스나 컨트롤러 계층에서 Google SDK 타입을 직접 참조하지 않는다.

### 6.2 환경별 자격증명 경로 분리

- 개발환경은 `/Users/johs/Documents/IntelliJ/sttgw/.local/credentials/google-stt-key.json`
- 운영환경은 `/APP/sttgw/credentials/google-stt-key.json`
- 실제 경로는 프로파일 설정으로만 관리하고, 코드에 하드코딩하지 않는다.

### 6.3 보수적 가용성 판별

- 자격증명 경로가 비어 있거나 파일이 없으면 `isAvailable()` 은 `false` 여야 한다.
- Google STT 호출 실패는 예외로 명시적으로 드러내고 로그를 남긴다.

### 6.4 테스트 우선 검증

- 실제 Google API 호출 전에도 컴파일과 테스트는 항상 통과해야 한다.
- 실서버 검증은 자격증명과 샘플 WAV 파일이 제공된 뒤 별도 검증으로 나눈다.

## 7. Google Cloud 준비 절차

7차 구현 후 실제 연동 검증을 위해 아래 절차가 필요하다.

1. Google Cloud 프로젝트 생성 또는 기존 프로젝트 선택
2. Billing 활성화
3. `Cloud Speech-to-Text API` 활성화
4. 서비스 계정 생성
5. 서비스 계정 키를 JSON 으로 발급
6. 개발환경에는 JSON 키를 `.local/credentials/google-stt-key.json` 경로에 배치
7. 운영환경에는 JSON 키를 `/APP/sttgw/credentials/google-stt-key.json` 경로에 배치
8. 필요 시 운영환경에 `GOOGLE_APPLICATION_CREDENTIALS` 환경변수 설정
9. 테스트용 짧은 WAV 파일 1개 준비

## 8. 제외 범위

이번 7차에서는 아래 범위를 제외한다.

- 운영 서버에서의 실배포 자동화

- 장시간 통화에 대한 스트리밍 세션 재연결 최적화

- 타 벤더 STT 구현

## 10. 예상 리스크

### 10.1 Google 인증 미제공

- 자격증명이 없으면 실제 API 호출 성공 여부를 검증할 수 없다.
- 이 경우 7차는 “코드 구현 + 로컬 테스트 완료”까지만 진행된다.

### 10.2 스트리밍 계약 변경 영향

- `SttStreamingSession` 인터페이스가 바뀌면 이후 사용하는 계층도 영향을 받을 수 있다.
- 이번 차수에서는 현재 사용처를 함께 점검하며 최소 범위만 반영한다.

### 10.3 장시간 스트리밍 한계

- Google STT 스트리밍에는 세션 시간 제한과 재연결 고려가 필요할 수 있다.
- 이번 차수에서는 우선 기본 구현과 안정적인 종료 처리까지를 목표로 한다.
