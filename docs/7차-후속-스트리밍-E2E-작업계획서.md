# 7차-후속 스트리밍 E2E 연결 작업계획서

## 1. 목적

본 문서는 7차 구현 이후 남아 있는 핵심 공백인 스트리밍 E2E 연결 작업을 정의한다.  
목표는 `RTP PCM 청크 -> Google STT 스트리밍 -> transcript 저장 -> WebSocket 실시간 전송` 경로를 실제 런타임 플로우로 연결하는 것이다.

## 3. 현재 상태

- `GoogleSttAdapter` 및 `GoogleSttStreamingSession`은 구현되어 있다.
- `SessionEventListener` 기반으로 `onAudioChunk` 이벤트는 발생한다.
- 하지만 오디오 청크를 Google STT 스트리밍 세션으로 전송하는 서비스 계층이 없다.
- STT 결과를 `STT_TRANSCRIPT`로 저장하고 WebSocket `STT_RESULT`로 브로드캐스트하는 실연결도 없다.

## 4. 작업 목표

1. `stt` 패키지에 스트리밍 오케스트레이션 서비스 추가
2. 채널(RX/TX) 단위 스트리밍 세션 생성/재사용
3. STT 콜백 결과를 DB에 저장
4. STT 콜백 결과를 WebSocket으로 전송
5. 통화 종료 시 세션 정리 및 close 보장
6. 단위 테스트로 핵심 플로우 검증

## 5. 작업 범위

### 5.1 신규 서비스

- `SttStreamingService` (`SessionEventListener` 구현)
- 핵심 책임:
  - `onAudioChunk`: call/channel 별 스트리밍 세션 준비 및 전송
  - `onSessionCompleted`: 세션 정리
  - 콜백: transcript 저장 + websocket 전송

### 5.2 테스트

- `SttStreamingServiceTest`
- 검증 항목:
  - 오디오 청크 입력 시 스트리밍 세션 생성/전송
  - 콜백 결과 저장/브로드캐스트
  - 세션 종료 시 stop 호출

## 6. 설계 원칙

1. 모듈 경계 유지
   - STT 연동은 `SttAdapter` 인터페이스를 통해서만 사용
2. 이벤트 기반 유지
   - `SessionEventListener`를 통한 연동
3. 채널 분리
   - `callId + channel` 키로 스트리밍 세션 관리
4. 실패 격리
   - STT 예외가 세션 관리 흐름을 중단시키지 않도록 처리

## 7. 제외 범위

- 장시간 스트리밍 세션 재연결/롤오버 최적화
- 실서비스 부하 테스트
- 운영 서버 자동화 스크립트 확장

## 8. 상세 작업 순서

1. 본 계획서 작성 후 문서만 커밋/푸시
2. `SttStreamingService` 구현
3. 단위 테스트 추가
4. `./gradlew compileJava`
5. `./gradlew test`
6. 코드 커밋/푸시

## 9. 리스크

1. 중간결과(interim) 빈도가 높아 DB 쓰기량 증가 가능성
2. 네트워크/인증 오류 시 스트리밍 세션 실패 가능성
3. 세션 종료 누락 시 리소스 누수 가능성

## 10. 완료 기준

1. 오디오 청크가 STT 스트리밍 세션으로 전달된다.
2. STT 결과가 `STT_TRANSCRIPT` 테이블로 저장된다.
3. STT 결과가 WebSocket으로 전송된다.
4. 통화 종료 시 관련 스트리밍 세션이 종료된다.
5. `compileJava`, `test` 모두 성공한다.
6. 작업이 한국어 커밋 메시지로 푸시된다.
